# Playbook · 巡页（LLM 驱动的页面巡检）

## 1. 业务定位

巡页（Patrol）是平台内置的「无需编写测试代码」的页面巡检能力：配置入口页（可追加多个补充入口），平台为入口页与补充状态分别做快照，再由规划模型生成探索用例、补全模型补齐未覆盖元素，经预算与风险控制后执行，最后用视觉模型或 DOM 规则判定页面是否正常，并把截图、录屏、控制台日志与 DOM 归档。

一次巡页任务由 **1 个主入口 Run + N 个补充入口 Run** 组成；每个 Run 是独立子任务，共用场景配置、模型、认证与审批策略。

适用场景：

- 新功能上线后，快速确认入口页关键交互是否可用
- 没有现成自动化用例时，对页面做一轮「模糊探索」
- 定时巡检核心页面，尽早发现白屏、报错、交互失效
- 为开发提供带截图/录屏/控制台的问题证据

与 UI 自动化任务的区别：

| 维度 | UI 自动化任务 | 巡页 |
|------|---------------|------|
| 用例来源 | 仓库中的 Playwright 测试代码 | 规划模型根据各 Run 的状态快照生成 |
| 执行对象 | 代码仓库 + 分支 | 入口 URL + 补充入口（前置操作或起始地址） |
| 判定方式 | 测试断言 | 视觉模型 + DOM/控制台规则 |
| 审批 | 无 | 写操作/危险操作需审批（可配置自动审批） |
| 主要产物 | 日志、Trace、视频、报告 | 用例录屏、步骤截图、控制台、DOM、发现项 |

## 2. 前置条件与权限

- `OPERATOR` / `ADMIN` 可创建/编辑/复制/删除巡页、配置模型、立即执行、审批与取消；`VIEWER` 只读。
- 执行前必须为巡页选择**规划模型**与**判定模型**，判定模型必须支持图片输入（Vision）；**解析模型**与**补全模型**可选，未选择时回退规划模型。模型配置在「巡页 → 模型配置」中维护。
- 服务端需可访问目标页面地址；需要登录时在巡页中配置认证信息（Cookie / Token / Local Storage）。
- 产物写入 MinIO；模型日志为敏感信息，**仅超级管理员**可见。

## 3. 功能与操作说明

入口：空间菜单「UI 自动化 → 巡页」，路由 `/spaces/{spaceId}/patrol`。

### 3.1 巡页列表

页面工具栏在卡片头部，右侧为「模型配置」与「新建巡页」。

| 列 | 含义 |
|----|------|
| 名称 | 巡页名称 + 描述 |
| 模型配置 | 解析、规划、补全、判定四类模型；解析/补全未配置时显示「复用规划模型」 |
| 预算 | 时长、可见文本字符上限 |
| 总 Token 消耗 | 该巡页历史任务的 Token 消耗汇总（含补充 Run） |
| 定时 | 「已开启」标签 + 可读的执行时间（如「每天 02:30」「每周一、周三 02:30」）；未开启显示「手动」 |
| 最近执行 | 最近一次任务创建时间 |
| 操作 | 执行 / 历史 / 编辑 / 复制 / 删除 |

列表每 3 秒自动刷新，用于观察运行中的任务。

### 3.2 新建 / 编辑巡页

| 分组 | 字段 | 说明 |
|------|------|------|
| 基础信息 | 名称 | 必填，空间内唯一，≤128 字符 |
| 基础信息 | 描述 | 可选，≤512 字符 |
| 基础信息 | 入口 URL | 必填，`http/https`，≤2048 字符 |
| 基础信息 | 浏览器 | `chromium` / `chrome` / `firefox` / `edge`，默认 `chromium` |
| 基础信息 | 运行模式 | 无头 / 有头，默认无头 |
| 模型配置 | 解析模型 | 可选，解析补充入口的前置描述；留空回退规划模型 |
| 模型配置 | 规划模型 | 必填，生成主入口与补充 Run 的用例 |
| 模型配置 | 补全模型 | 可选，生成覆盖率补全用例；留空回退规划模型 |
| 模型配置 | 判定模型 | 必填，必须支持图片输入（视觉） |
| 执行限制 | 时长预算 | 1~60 分钟，默认 20 分钟，每个 Run 独立计时 |
| 执行限制 | 页面文本上限 | 100~100000 字符，默认 1800 |
| 执行限制 | 滚动扫描 | 默认开启，扫描页面可视区外的可交互元素 |
| 执行限制 | 用例录屏 | 默认开启，每条用例独立录屏 |
| 场景补充 | 补充入口 | 可追加多条；每条支持「操作型 / URL 型」、前置描述、起始地址、关注点、启用开关 |
| 场景补充 | 一键填入示例配置 | 新增/编辑补充入口弹窗右上角，填入示例后可按实际页面修改 |
| 认证与授权 | 认证方式 | `NONE` / `COOKIE` / `TOKEN` / `LOCAL_STORAGE` |
| 认证与授权 | 认证内容 | Cookie、Bearer Token 或 Local Storage JSON，密文保存 |
| 认证与授权 | 自动批准写操作 | 默认关闭；开启后写操作（含补充入口前置）无需人工审批 |
| 认证与授权 | 自动批准危险操作 | 默认关闭；删除等不可逆操作需显式开启 |
| 定时 | 启用定时 | 开启后按设定的频率与时间自动创建任务 |
| 定时 | 执行频率 / 时间 | 前端按「每天 / 每周（多选星期）/ 每月（选择日期）/ 自定义」配置，保存时自动转换为 6 段 Cron；无需手工填写 Cron |

补充入口字段说明：

| 字段 | 说明 |
|------|------|
| 入口类型 | `操作型（ACTION）`：从入口页执行前置操作后进入目标状态；`URL 型`：直接打开指定页面作为补充 Run |
| 前置描述 | 操作型必填；一行一个动作，建议用「」标注页面文案；技术上限 20 步、≤1024 字符 |
| 起始地址 | URL 型必填；仅允许同主机地址或同源相对路径，≤2048 字符 |
| 名称 | 补充 Run 的展示名称；留空自动取前置描述/地址前 32 字，≤128 字符 |
| 关注点 | 可选，≤200 字符；作为该补充 Run 的用例规划侧重点 |
| 启用 | 关闭后保留配置，但执行主任务时跳过 |

「复制」会打开新建弹窗并带入原巡页配置，名称自动加「副本」，保存后生成新的巡页。

### 3.3 模型配置

「模型配置」抽屉维护当前空间的巡页模型：

- 列表展示名称、Base URL、模型 ID、能力标签（视觉 / 工具调用 / JSON 输出）、启用状态与最近测试结果。
- 支持新建、编辑、删除、测试连通性。删除被巡页引用的模型会导致该巡页无法规划/判定，删除后需回到巡页重新选择模型。
- 新建时 API Key 必填；编辑时留空表示保持原 Key。
- 能力参数默认勾选「支持图片输入」「支持工具调用」「支持 JSON 输出」，按模型实际情况调整；判定模型必须保留「支持图片输入」。
- Base URL 默认不填，需填写 OpenAI 兼容端点（如 `https://api.openai.com/v1`）。

### 3.4 立即执行

点击「执行」会创建一次手动任务。触发前服务端校验：

1. 巡页已配置规划模型与判定模型（解析/补全模型可留空回退）；
2. 该巡页没有处于活动状态的任务；
3. 平台并发未达到上限（默认 10，可排队 100）。

校验失败会直接提示原因，不会创建任务。创建成功后自动打开该巡页的执行历史。

### 3.5 执行历史

| 区域 | 内容 |
|------|------|
| 汇总卡片 | 平均 Token、平均元素覆盖率、平均耗时（仅统计已结束任务） |
| 表格 | 状态、用例通过/总数、耗时、Token、覆盖率、触发方式、创建时间、操作 |
| 操作 | 详情 / 取消（活动任务）/ 删除（已结束任务） |
| 分页 | 右下角，`total + sizes + prev/pager/next`，默认 10 条/页 |

删除任务会同时清理该任务的快照、用例录屏、步骤截图、控制台与 DOM。

### 3.6 任务详情

抽屉标题为「巡页任务」，包含三个 tab：

1. **概览**：状态、触发方式、场景与入口、耗时、结果说明；统计卡片（Run 数 / 已执行 Run、用例通过、元素覆盖、失败用例、LLM Token、保留至）；降级提示、可见文本截断提示与**解决建议**（失败/降级时按错误类型给出可执行动作）；执行信息（审批人/审批时间、开始/结束、当前阶段）与模型快照（解析 / 规划 / 补全 / 判定）。
2. **用例**：按 Run 分组展示（主入口、`[补充] 名称`…）；组头显示 Run 状态、覆盖率、耗时、Token；可按「全部 / 成功 / 失败」筛选。每个用例展示意图、期望、判定原因、风险等级；展开后可看录屏与步骤明细（动作、目标、风险与授权、结果、截图、信息），以及最终截图、控制台日志、DOM。
3. **模型日志**：仅超级管理员可见。按阶段展示 `PLAN`（规划）、`COVERAGE`（覆盖率补全）、`RESOLVE`（补充前置解析）、`JUDGE`（判定）的模型、用途、状态、Token、耗时与错误；可展开查看完整系统/用户上下文和模型原始输出。

活动中的任务每 2 秒刷新详情；任务结束后停止刷新。

### 3.7 审批

任务停在「待审批」时，详情顶部出现审批卡片：

| 操作 | 效果 |
|------|------|
| 批准并执行 | 授权写操作；「允许危险操作」开关打开时才授权删除等不可逆操作 |
| 全部拒绝（仅只读） | 只执行只读用例，写/危险用例不执行 |

审批请求会记录审批人、审批时间与授权的用例 ID；审批后任务继续执行，无需重新创建。

补充入口参与同一次审批：

- 所有 Run 规划出的风险合并计算，一次任务只产生一张审批卡，子任务不单独审批。
- 前置操作包含写/危险动作时，审批前**不执行前置、不采集状态快照**；审批通过后才执行前置、补采快照并规划该 Run 的用例。
- 主任务失败或取消时，仍在等待审批的补充 Run 会一并取消。

## 4. 关键规则与限制

### 4.1 任务状态

| 状态 | 前端文案 | 含义 |
|------|----------|------|
| `QUEUED` | 待执行 | 已创建，等待执行 |
| `RUNNING` | 执行中 | 正在快照、规划、执行或判定 |
| `WAITING_APPROVAL` | 待审批 | 用例已生成，等待人工授权 |
| `COMPLETED` | 已完成 | 执行结束并完成判定（可能带降级） |
| `FAILED` | 失败 | 准备/快照/执行阶段失败，或恢复逻辑判定失败 |
| `CANCELED` | 已取消 | 用户取消并已停止 |

### 4.2 执行阶段

`PREPARING`（安装依赖/准备执行环境）→ `SNAPSHOTTING`（入口页 / 补充状态快照）→ `PLANNING`（生成用例与覆盖率补全）→ `WAITING_APPROVAL`（可选）→ `EXECUTING`（逐用例执行）→ `JUDGING`（视觉/规则判定）→ `FINISHED`（归档与收尾）。

补充入口 Run 额外包含：`RESOLVING`（前置描述解析）→ 执行前置 → `SNAPSHOTTING`（补充状态快照）。前置包含写/危险操作时，`RESOLVING` 后先停在 `WAITING_APPROVAL`，审批通过后才继续。主任务需等待所有补充 Run 结束才进入 `FINISHED`。

### 4.3 预算与降级

| 项 | 默认值 / 规则 |
|----|---------------|
| 时长预算 | 20 分钟；超时后停止继续执行，已产生的用例结果仍归档 |
| Token 消耗 | 仅统计展示，不设任务级上限；由模型配置的 maxTokens 约束单次输出 |
| 时长耗尽 | 任务标记「降级」，并记录停止原因；判定退回 DOM + 控制台规则 |
| 规划输出 | 单次输出上限取模型配置 maxTokens（8k/16k/32k/64k）；最多 8 步/用例；动作有白名单 |
| 判定输出 | 单次输出上限取模型配置 maxTokens（8k/16k/32k/64k）；需要对应 Run 的状态快照/失败步骤截图 |
| 模型调用 | 流式读取：空闲超时 120 秒（`PLATFORM_PATROL_LLM_TIMEOUT_SECONDS`）、单次调用总时长上限 1800 秒（`PLATFORM_PATROL_LLM_MAX_CALL_SECONDS`）；仅网络类失败重试，最多 2 次；图片长边压缩至 1568、JPEG 质量 0.8 |
| 环境准备 | 依赖安装超时 300 秒；入口页/补充状态快照超时最多 300 秒 |
| 页面操作 | 页面加载 20 秒；单步动作 5 秒 |
| 模型最大输出 | 模型配置中仅支持档位 8k/16k/32k/64k（8192/16384/32768/65536），默认 16k，思考与回答合计 |

降级（`degraded=true`）表示任务仍完成，但部分模型环节未按预期工作：无可用模型、Token 不足、模型调用失败或输出无法解析。降级原因与阶段状态在模型日志中可查。

**解决建议**：模型/预算失败会按错误类型生成可执行建议并写入任务（概览「解决建议」直接展示），例如：

- 超时/截断/推理耗尽：给出该模型当前 maxTokens 与建议档位（8k → 16k → 32k → 64k）；已是 64k 时建议改用非推理模型或降低页面文本上限；
- 余额不足、Key 无效、模型不存在、限流、网络不可达：分别给出充值/换 Key、核对 Base URL 与模型 ID、降低并发等动作；
- 时长预算耗尽、队列已满、快照/安装超时：给出调大预算或检查环境的动作。

### 4.4 风险与审批

- 用例风险等级：`READ` < `WRITE` < `AUTH` < `DESTRUCTIVE`；用例的 `worstRisk` 取步骤最高风险。
- 只含 `READ` 的用例自动通过；存在 `WRITE` / `AUTH` / `DESTRUCTIVE` 时任务进入待审批。
- 补充入口的前置描述也会做风险判定：填写/输入/按键，或文案命中「保存、提交、新增、编辑、登录、删除、支付、退款」等关键字时，前置按 `WRITE` / `DESTRUCTIVE` 处理，审批前不执行。
- 巡页开启「自动批准写操作」/「自动批准危险操作」后，对应风险无需人工审批。
- 审批只能针对「待审批」任务；已授权用例按 ID 校验，不能审批其他任务的用例。

### 4.5 执行与判定

- 主入口 Run 从入口页开始并做快照；补充 Run 先执行前置（或直接打开 URL），再对进入后的状态做快照，元素覆盖率按各 Run 的快照分别统计后汇总。
- 补充入口按状态独立规划与执行，与主入口并发；前置解析失败或执行时元素消失，该 Run 标记 `UNREACHABLE`，其用例 `SKIP`，不影响其他 Run。
- 每条用例使用独立浏览器上下文并录屏；补充 Run 的录屏包含前置过程；用例结束后额外等待 3 秒再结束录制，保留收尾画面。
- 每个元素操作/断言前都会把目标元素滚动到视口中央（含弹层、表格等内层滚动容器）并等待 200ms；每个步骤都留存截图（元素操作取操作前画面，失败时额外截取失败画面），确保录屏与截图都能看到目标元素。
- 用例执行失败（`FAILED`）直接判定失败并生成 P0 交互发现项。
- 模型判定基于截图 + 页面信息 + **控制台报错原文**：判定提示词会附上 `pageerror` / `error` / `warning` 的报错明细（相同文案合并并标注重复次数，按条数与字数预算截断），控制台错误数量只作为兜底统计；无关噪音（favicon/图片 404、统计脚本、跨域第三方资源）不作为失败依据。
- 模型不可用或输出不合法时退回规则判定（此时只用控制台错误数量兜底）：
  - 有失败步骤 → 失败，P0；
  - 控制台有错误 → 失败，P1；
  - 其他 → 通过。
- 发现项严重级别 `P0` / `P1` / `P2`；类型包括 `BLOCKER`、`INTERACTION`、`DISPLAY`、`COPY`、`CONSISTENCY`。

### 4.6 定时与并发

| 项 | 规则 |
|----|------|
| 配置方式 | 前端选择「每天 / 每周（多选星期）/ 每月（选择日期）/ 自定义」，保存时自动转为 6 段 Cron，无需手工输入 |
| 调度扫描 | 每 60 秒扫描到期巡页，创建定时任务并计算下次运行时间 |
| 调度跳过 | 未配置模型、同巡页已有活动任务、平台并发已满时跳过本次 |
| 下次运行时间 | 无论本次成功与否都会推进，避免同一时刻重复触发 |
| 平台并发 | 默认 10 个巡页任务并行；并行已满时手动执行进入排队（默认最多排队 100 个），定时执行跳过 |
| 取消 | `QUEUED` / `RUNNING` / `WAITING_APPROVAL` 均可取消；有活跃线程时协作停止（步骤/阶段边界与子进程检查取消标记），没有活跃线程（服务重启、线程已退出）时直接落库为 `CANCELED` |
| 服务重启 | 启动时把 `QUEUED` / `RUNNING` 标记为失败（`WAITING_APPROVAL` 保留，可继续审批），并输出回收条数日志 |
| 脏状态兜底 | 每 60 秒扫描一次：已取消但无活跃线程 → `CANCELED`；超过「时长预算 + 10 分钟」仍无活跃线程 → `FAILED（任务长时间无进展）` |

### 4.7 保留策略

| 项 | 规则 |
|----|------|
| 任务保留 | 默认 90 天，到期删除任务记录与全部证据 |
| 清理时间 | 每天 02:30（`platform.patrol.retention-cron`，默认 `0 30 2 * * *`） |
| 清理批量 | 每次最多 50 个任务 |
| 删除巡页 | 有活动任务时禁止删除；删除巡页会清理其历史任务与证据 |

## 5. 典型流程

### 5.1 首次配置并执行

1. 进入「巡页 → 模型配置」，新建规划模型与判定模型（判定模型勾选视觉能力），测试连通性；按需再建解析/补全模型。
2. 新建巡页：填入口 URL，选择解析/规划/补全/判定模型，按需调整预算、认证与定时。
3. 如需巡检入口页之外的页面，在「场景补充」中新增补充入口：操作型填前置描述，URL 型填起始地址；可点「一键填入示例配置」后修改。
4. 点「执行」，确认任务进入「执行中」。
5. 若任务进入「待审批」，在详情中查看将要执行的写/危险用例（含补充入口前置），选择「批准并执行」或「全部拒绝」。
6. 执行完成后查看各 Run 的用例与发现项，下载录屏/截图给开发。

### 5.2 定时巡检

1. 在巡页中开启定时，选择执行频率与时间（每天 / 每周多选星期 / 每月选择日期 / 自定义），前端自动生成 Cron。
2. 确认巡页模型可用、预算合理；定时重复时会跳过已有活动任务的巡页。
3. 次日从「历史」查看任务；定时任务被跳过时检查活动任务与平台并发。

### 5.3 排查一次降级任务

1. 打开任务详情，看概览中的结果说明与「降级」标记。
2. 切到「模型日志」（超级管理员），确认是 `PLAN`、`COVERAGE`、`RESOLVE` 还是 `JUDGE` 阶段降级。
3. 按状态区分：`SKIPPED` 多为未配置模型或时长耗尽；`FAILED` 看错误信息与原始输出；`DEGRADED` 看是否退回规则判定。
4. 若是时长不足，调大时长预算或缩小巡检范围；补充入口规划偏离时优化「关注点」；若是模型调用失败（超时/截断/推理耗尽），先在模型配置中调大 maxTokens 或换非推理模型。

## 6. 常见问题

| 现象 | 排查 |
|------|------|
| 点「执行」直接提示未配置模型 | 巡页必须选择规划模型与判定模型；解析/补全模型可留空，留空时回退规划模型 |
| 提示已有任务在执行 | 同一巡页同一时间只允许一个活动任务；等结束或取消后再执行 |
| 提示队列已满 | 平台默认 10 个并行 + 100 个排队；等待其他任务结束 |
| 任务卡在「待执行」 | 执行线程繁忙或服务刚重启；查看服务日志与队列 |
| 一直停在「执行中」 | 看当前阶段：准备/快照阶段多为环境或网络；执行阶段看用例与录屏；超过「时长预算 + 10 分钟」会被自动标记为失败 |
| 取消后状态不变 | 正常会先进入协作取消；若无活跃执行线程（服务重启过），取消会立即落库为已取消；仍不变时等 60 秒兜底扫描 |
| 进入「待审批」但没有审批按钮 | 只有「待审批」状态可审批；确认任务未结束、非取消 |
| 判定结果全是规则判定 | 查看模型日志：可能模型未配置、调用失败、Token 不足或输出无法解析 |
| 覆盖率偏低 | 页面元素在折叠区或 iframe 中；开启滚动扫描，必要时调大页面文本上限让模型看到更多元素信息 |
| 录屏缺失 | 巡页关闭了录屏，或用例未开始执行；在巡页配置中开启「用例录屏」 |
| 产物下载 403 / 过期 | 证据通过预签名 URL 下载，过期后重新打开任务详情获取新链接 |
| 补充入口没有执行 | 入口是否启用；操作型前置是否解析失败（Run 为 `UNREACHABLE`）；URL 型地址是否同主机；前置是否因写/危险操作停在待审批 |
| 补充入口用例覆盖偏低 | 「关注点」是否为空或过于笼统；前置是否进入了错误页面；可先点「解析预览」确认前置步骤 |
| 定时任务没有触发 | 巡页是否开启定时、执行时间是否已保存；是否因活动任务/并发被跳过 |
| 历史任务消失 | 任务按 90 天保留，到期由每日 02:30 清理任务与证据 |
| 看不到「模型日志」tab | 仅超级管理员可见，普通管理员也看不到 |
| 删除巡页失败 | 该巡页仍有活动任务；先取消或等待结束 |
