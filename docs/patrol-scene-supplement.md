# 巡页 · 场景补充（补充入口 Run）需求 v3

> 状态：已实现（后端 V36 / V37，前端巡页弹窗已接入）。
> 关联：`docs/playbooks/12-patrol.md`（现有巡页能力）。

## 1. 背景与目标

现有巡页只覆盖入口 URL 的页面。同一页面中的弹层、抽屉、Tab、任务详情等状态无法被规划与覆盖。

「场景补充」允许在巡页配置中追加若干“起始状态”：每条是一句自然语言前置（如“点击详情按钮”）或一个起始地址；系统解析为可执行步骤，在该状态上独立执行一遍现有全流程（进入 → 快照 → 规划 → 执行 → 判定），与主入口并列汇总。

一次巡页任务 = **1 个主入口 Run + N 个补充入口 Run**，每个 Run 都是一条独立任务（独立 context、预算、用例、证据）。

## 2. 已确认决策

1. 补充入口与主入口共用场景配置；写/危险操作由场景的「自动批准写操作」「自动批准危险操作」统一决定，补充入口不单独限制只读。
2. 所有 Run 并发执行；每个 Run 都是独立任务，并发由平台现有「任务总并发 + 排队」控制，不再增加单任务并发上限。
3. 实现方案：复用任务表，补充入口新增子任务行（`parent_task_id` 关联），复用现有规划/执行/判定流程。
4. 不新增预算限制：Token 预算、用例数上限均已删除；**时长预算保留**（每个 Run 各自使用场景配置的时长预算）；前置步数不设业务上限，仅保留技术上限 20 步防误配；补充条数不设上限。
5. 提示词配置由 3 个模块扩展为 **4 个固定模块**：`PLAN`（规划）、`SUPPLEMENT`（覆盖率补全）、`JUDGE`（视觉判定）、`RESOLVE`（前置解析）；超管可见、可覆盖，默认值随版本内置。
6. **四类模型分别独立配置**：巡页新增「解析模型」与「补全模型」选择，分别用于补充前置解析与覆盖率补全；判定继续使用判定模型。解析/补全未配置时各自回退规划模型，并在配置页提示。
7. 前置解析采用**两层策略**：确定性匹配优先（0 Token），LLM 仅在多候选、序数/复合指令或口语化描述时兜底。

## 3. 名词

| 名词 | 含义 |
|---|---|
| 主入口 Run | 巡页入口 URL 对应的任务（现有流程） |
| 补充入口 Run | 由一条场景补充创建的子任务，与主入口同级 |
| 补充前置 | 进入该状态的操作：自然语言或起始地址 |
| 前置解析 | 将自然语言映射为 `action + selector` 的可执行步骤 |
| 状态快照 | 执行前置后采集的元素、可见文本、截图（该 Run 的规划依据） |
| 关注点 | 可选，补充入口的测试重点；默认“覆盖该状态主要交互” |
| UNRESOLVED / UNREACHABLE | 前置无法解析 / 执行时走不到该状态；其用例 SKIP，不算失败 |

## 4. 配置项（新建/编辑巡页）

新增「场景补充」区块：

| 字段 | 规则 |
|---|---|
| 名称 | 可选，留空自动取前置描述/地址前 32 字；≤128 字 |
| 类型 | 操作型（自然语言）/ URL 型（起始地址，如 `/demo/list?id=1`） |
| 前置描述 | 操作型必填；一行一个动作，建议用「」标注页面文案；技术上限 20 步、≤1024 字 |
| 起始地址 | URL 型必填；仅允许同主机地址或同源相对路径，≤2048 字 |
| 关注点 | 可选，≤200 字；为空时按通用巡检目标规划 |
| 启用 / 排序 | 支持；关闭后保留配置但执行时跳过 |
| 解析结果 | 弹窗内支持「解析预览」；保存时持久化步骤与置信度，执行时优先复用（暂不支持手工编辑步骤/元素点选） |
| 示例配置 | 弹窗右上角「一键填入示例配置」，填入后可修改 |

**模型与提示词配置**
- 巡页模型选择新增「解析模型」「补全模型」（均可选）：不配置时各自回退规划模型；
- 提示词配置新增固定模块 `RESOLVE`（前置解析），与现有三个模块并列，仅超管可见/可改；
- 解析器使用 `RESOLVE` 提示词 + 巡页选择的解析模型；
- 覆盖率补全使用 `SUPPLEMENT` 提示词 + 巡页选择的补全模型。

- 条数不设上限；
- 前置动作与用例动作都使用场景级审批配置，不单独设开关；
- 写操作前置在审批前不得执行（见第 6 节）。

## 5. 任务模型

```
主人任务（现有 patrol_task，status=RUNNING）
  ├─ 主入口流程：入口快照 → 规划 → 执行 → 判定
  └─ 子任务（parent_task_id=主任务，entry_type=SUPPLEMENT）
        ├─ 前置解析 → 进入状态 → 状态快照 → 规划 → 执行 → 判定
        └─ 与主入口并发执行，独立 context / 录屏 / 用例 / 证据
```

- 补充入口是**独立任务行**，与主入口共用场景、模型、认证、审批配置；
- 历史列表默认只展示主任务（`parent_task_id is null`），子任务在任务详情中按 Run 分组展示；
- 任务统计、Token、用例数、发现项由主任务汇总子任务；
- 取消主任务 → 级联取消所有子任务；
- 主任务在所有子任务结束后才收尾；等待期间需心跳/兜底规则（见第 10 节）。

## 6. 审批

- 风险来源：主入口与所有补充入口规划出的用例风险合并计算；
- 场景开启「自动批准写/危险」→ 对应风险自动放行，无需人工；
- 未开启 → 一次任务只产生**一次审批**，覆盖所有 Run 的用例；子任务不单独展示审批卡；
- 补充前置包含写操作时：
  - 审批前**不执行前置、不采集状态快照、不规划该 Run 用例**，子任务停在 `WAITING_APPROVAL`；
  - 审批通过（或场景已自动批准）后，才执行前置 → 采集状态快照 → 规划该 Run 用例 → 执行；
  - 审批被拒绝 / 主任务取消时，该 Run 不执行并记录原因；
  - UI 提示：`保存后由平台在任务执行时解析前置；包含写操作的补充入口会在审批后才采集状态快照。`

## 7. 前置解析

分两层执行，优先不花钱、可复现的第一层：

**第一层：确定性匹配（默认，0 Token）**
- 输入：前置描述中的文案（「」内容）与入口页快照元素；
- 规则：精确文案 → 包含文案 → 角色优先级（按钮 > 链接 > 其他）；
- 唯一高置信命中 → 直接产出步骤，不调用模型；
- 解析失败/多候选/序数或复合指令（“第一行”“点击历史后点击详情”）→ 进入第二层。

**第二层：LLM 兜底（调用解析模型 + RESOLVE 提示词）**
- 输入：前置描述 + 元素清单（selector / role / text / frame）；
- 输出约定：`{"steps":[{action, selector, target, confidence, reason}], "unresolvedReason": ""}`；
- 校验：selector 必须存在于快照元素中，否则重试一次；仍失败则 `UNRESOLVED`；
- 置信度低于阈值或存在多候选 → 标记“待确认”，可调整前置描述后重新点「解析预览」。

**其他规则**
- 解析结果缓存到补充项配置与任务快照；执行失败时重试解析一次并记录；
- 当前版本暂不支持“从页面选择元素”，元素点选为后续增强项；
- 失败提示：`未找到文案含「详情」的元素，请检查文案或改用 URL 型`；
- 模型日志新增阶段 `RESOLVE`，记录模型、Token、耗时、原始输出与失败原因。

## 8. 执行与失败语义

- 每条用例从入口 URL 全新 context 开始 → 重放该 Run 的前置 → 执行用例步骤；
- 前置失败/元素消失：Run 标 `UNREACHABLE`，用例 `SKIP（起始状态不可达）`，不算失败，也不写入发现项；
- 执行完成自动清理现场；
- 录屏与截图包含前置过程，可看到“如何进入该状态”。

## 9. 预算与限制

| 项 | 规则 |
|---|---|
| Token 预算 | 已删除，不恢复 |
| 用例数上限 | 已删除，不恢复 |
| 补充条数 | 不设上限 |
| 前置步数 | 无业务上限，技术上限 20 步 |
| 时长预算 | 保留；每个 Run 各自使用场景配置的时长预算；主任务等待子任务期间不计入主任务预算，也不会因等待被判超时 |
| 并发 | 复用平台任务总并发与排队；主任务与每个补充 Run 各占一个并发名额（默认 10 并发 + 100 排队），不新增单任务并发限制 |
| 技术性超时 | 依赖安装 300s、入口快照 300s、页面加载 20s、单步动作 5s、模型单次调用上限 1800s |

## 10. 覆盖率与统计

| 指标 | 口径 |
|---|---|
| 补充场景覆盖率 | 已执行的补充子任务 / 已启用的补充项 |
| 元素覆盖率 | 主入口与各 Run 的状态快照分别统计后汇总 |
| 用例统计 | 主任务汇总主入口 + 子任务的通过/失败/SKIP |

任务概览展示：Run 数、已执行 Run 数、各 Run 用例与覆盖率、总 Token。

## 11. 界面

**巡页编辑**
- 「场景补充」列表：名称、类型、前置/地址、启用、排序、解析状态；
- 新增/编辑弹窗：类型切换、前置输入、起始地址、关注点、解析预览、「一键填入示例配置」；元素点选暂未实现；
- 写操作前置提示：审批后才能生成状态快照。

**任务详情**
- 用例 tab 按 Run 分组：`主入口`、`[补充] 任务详情`…；组头显示 Run 状态、覆盖率、耗时、Token；
- Run 详情：前置步骤、状态快照截图、该 Run 模型日志；
- 审批卡一次展示所有 Run 的风险用例；
- 历史列表仍一条主任务。

## 12. 数据与接口（方案 B）

```
patrol_scene（新增字段）
  resolve_model_id（可空，为空回退规划模型）
  supplement_model_id（可空，为空回退规划模型）
  supplements_json（v1 以 JSON 数组存储补充项配置，数量不限；
                    每项含 name/entryType/preconditionText/startUrl/focusText/enabled/steps/confidence）

patrol_task（新增字段）
  parent_task_id, entry_type(MAIN/SUPPLEMENT), entry_label, setup_steps_json

patrol_case / patrol_case_step：沿用，按 task_id 归属到各自 Run
```

接口：
- 场景创建/更新请求与响应增加 `supplements`（数组）与 `supplementModelId`；
- 任务详情响应增加 `runs`（子任务分组信息）；
- 取消主任务级联取消子任务。

## 13. 验收标准

1. 配置 3 条补充项后执行一次任务：主入口 + 3 个补充 Run 并发执行，各自归档；
2. 主入口行为与现状一致，无回归；
3. 补充用例录屏包含前置过程；状态快照基于前置执行后的页面；
4. 前置元素消失：该 Run `UNREACHABLE`，用例 SKIP，不影响其他 Run；
5. 场景开启自动批准写操作后，补充 Run 的写用例直接执行；未开启时只出现一次审批，覆盖所有 Run；
6. 写操作前置：审批前无状态快照，审批后补采并规划；
7. 取消主任务后，所有子任务停止并标记取消；
8. 不配置补充项时行为与改造前完全一致；
9. “点击「详情」”这类简单前置由确定性匹配直接解析，不产生 LLM 调用与 Token；
10. 复杂前置（“第一行详情”“点击历史后点击详情”）走 `RESOLVE` 提示词 + 解析模型，模型日志出现 `RESOLVE` 阶段记录；
11. 提示词配置页展示 4 个固定模块（规划/补全/判定/前置解析），超管可编辑、可恢复默认；
12. 巡页未配置“解析模型”/“补全模型”时各自回退规划模型，配置页有提示；
13. 补全模型单独选择后，覆盖率补全按该模型执行；模型日志 `COVERAGE` 阶段记录对应模型；
14. 补充入口弹窗点击「一键填入示例配置」可自动填充示例字段，修改后保存正常。

## 14. 兼容与降级

- 旧任务无 `parent_task_id` / 补充数据：按主入口展示，不报错；
- 子任务创建失败（队列满等）：主任务记录该 Run 失败原因并继续，不阻塞其他 Run；
- 前置解析失败、状态快照失败、规划失败：仅该 Run 降级，并在概览给出解决建议（复用现有 advice）。
