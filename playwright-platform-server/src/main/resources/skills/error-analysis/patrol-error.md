# 巡页巡检排查 SOP

## 1. 适用场景

- 巡页任务一直 `QUEUED` / `RUNNING`，或停在 `WAITING_APPROVAL` 不动
- 点「执行」被拒绝：未配置模型、已有任务在执行、并发已满
- 任务完成但带「降级」，判定结果不可信
- 用例大面积失败、覆盖率异常偏低、录屏/截图/控制台缺失
- 定时巡页到点不触发，或历史任务提前消失
- 模型配置保存/测试失败，判定模型不可用

## 2. 先分清对象

| 对象 | 特征 | 不要混淆 |
|------|------|----------|
| 巡页任务 | 入口是 URL，用例由 LLM 生成，有审批/覆盖率/模型日志；可能包含 1 个主入口 Run + N 个补充入口 Run | 不是「场景 → 任务」的 Playwright 回归 |
| UI 自动化任务 | 有仓库、分支、安装/测试阶段日志、Trace | 不要拿巡页的阶段去套 `INSTALLING` / `TESTING` |
| 巡页配置 | 名称、入口 URL、四类模型、预算、认证、补充入口、可视化定时、自动审批 | 配置错误通常在执行前就被拒绝 |
| 模型配置 | Base URL、模型 ID、视觉/工具/JSON 能力 | 模型不可用会导致规划、覆盖率补全、前置解析或判定降级 |

> 助手当前没有巡页专用只读工具时，不要假装调用 `getTask` 或编造任务字段；要求用户提供巡页名称/任务 ID、状态、当前阶段，以及（超级管理员）模型日志截图。

## 3. 排查步骤

### 第 1 步：确认任务状态与当前阶段

| 观察 | 判断 |
|------|------|
| `QUEUED`，长时间不开始 | 执行线程繁忙、服务刚重启、任务队列积压 |
| `RUNNING` + `PREPARING` 长时间不变 | Runner 环境准备卡住、镜像/依赖安装失败 |
| `RUNNING` + `SNAPSHOTTING` 长时间不变 | 入口 URL 或补充入口目标页不可达、登录态失效、页面加载超时 |
| `RUNNING` + `RESOLVING` 长时间不变 | 仅补充入口：解析模型调用慢/超时，或前置文案无法匹配 |
| `RUNNING` + `PLANNING` 长时间不变 | 规划/补全模型调用慢/超时，或时长预算即将耗尽 |
| `WAITING_APPROVAL` | 正常：存在写/认证/危险用例，或补充入口前置含写/危险动作，等待审批 |
| `RUNNING` + `EXECUTING` 长时间不变 | 用例步骤卡住、目标页面无响应、录制未结束 |
| `RUNNING` + `JUDGING` 长时间不变 | 判定模型调用慢/超时 |
| `COMPLETED` + `degraded=true` | 链路完成但模型环节降级，判定可信度下降 |
| `FAILED` | 准备/快照/执行失败，或服务重启恢复 |
| `CANCELED` | 协作式取消，等待当前步骤结束 |

### 第 2 步：检查巡页配置

| 检查项 | 说明 |
|--------|------|
| 入口 URL | 是否可访问、是否需要登录、是否被内网/VPN 限制 |
| 解析 / 规划 / 补全 / 判定模型 | 规划、判定必须选择；解析/补全留空时回退规划模型；判定需勾选「支持图片输入」 |
| 补充入口 | 是否启用；操作型前置是否与页面真实文案一致；URL 型是否同主机；关注点是否为空 |
| 时长预算 | 是否过小；时长耗尽会停止继续执行并触发降级（每个 Run 独立计时） |
| 页面文本上限 / 滚动扫描 | 文本上限过小或未滚动会漏元素，覆盖率偏低 |
| 用例录屏 | 是否开启；关闭后没有录屏属正常 |
| 认证方式与内容 | Cookie/Token/Local Storage 是否过期或格式错误 |
| 自动批准写/危险操作 | 未开启时任务会停在待审批，属正常保护；补充入口写前置同样受此控制 |
| 定时 | 是否开启；执行频率与时间是否已保存（无需人工校验 Cron） |

### 第 3 步：检查模型配置

| 检查项 | 说明 |
|--------|------|
| Base URL | OpenAI 兼容端点是否正确，是否需要 `/v1` |
| 模型 ID | 是否与服务商实际模型名一致 |
| API Key | 是否有效、是否过期、是否有额度 |
| 视觉能力 | 判定模型必须支持图片输入；未勾选会导致判定不可用 |
| 测试连通性 | 在「模型配置」中点测试；失败先修模型，不要重跑巡页 |
| 删除影响 | 删除被引用的模型会让巡页无法规划/判定，删除后需重新选择模型 |

### 第 4 步：查看模型日志（仅超级管理员）

模型日志按阶段记录，是区分「模型问题」与「执行问题」的关键证据：

| 阶段 | 用途 | 关注点 |
|------|------|--------|
| `PLAN` | 生成探索用例 | 是否 `SKIPPED`/`FAILED`、原始输出是否为空或非法 JSON |
| `COVERAGE` | 覆盖率补全（补全模型） | 是否因 Token 不足跳过、补全用例是否重复 |
| `RESOLVE` | 补充入口前置解析（解析模型） | 是否找不到目标文案、步骤置信度低、元素歧义 |
| `JUDGE` | 用例判定 | 是否退回规则判定、截图是否缺失、输出是否可解析 |

| 状态 | 含义 | 处理方向 |
|------|------|----------|
| `SUCCESS` | 模型调用并解析成功 | 继续看执行与判定结果 |
| `DEGRADED` | 调用了模型但结果不完整/退回规则 | 看错误信息与原始输出 |
| `FAILED` | 调用失败或解析失败 | 先测模型连通性与 Key/额度 |
| `SKIPPED` | 未调用（无模型、时长耗尽、阶段不需要） | 补模型或调大时长预算 |

### 第 5 步：检查执行与证据

- 用例执行状态：`PENDING`、`SUCCESS`、`FAILED`、`SKIPPED`、`BLOCKED`。
- 执行失败通常对应 P0 交互发现项；判定失败需看判定原因与发现项。
- 补充入口 Run 单独看：`entry_type=SUPPLEMENT`，状态可能是 `WAITING_APPROVAL`、`UNREACHABLE`（前置解析失败/元素消失），其用例为 `SKIP`。
- 证据缺失时分别核对：各 Run 的状态快照、用例录屏（补充 Run 含前置过程）、步骤截图、最终截图、控制台、DOM。
- 证据下载 403/过期：预签名 URL 过期，重新打开任务详情获取新链接。

### 第 6 步：检查调度与保留

| 现象 | 检查 |
|------|------|
| 定时不触发 | 定时是否开启、执行时间是否已保存、服务是否运行 |
| 到点但没有任务 | 未配置模型、同巡页已有活动任务、平台并发已满会被跳过 |
| `nextRunAt` 不推进 | 调度扫描异常；调度器每 60 秒扫描一次 |
| 历史任务消失 | 默认保留 90 天，每天 02:30 清理到期任务与证据 |
| 删除巡页失败 | 仍有活动任务，先取消或等待结束 |

## 4. 阶段 → 根因映射

| 卡住阶段 | 可能根因 | 验证动作 |
|----------|----------|----------|
| `PREPARING` | Runner 不可用、镜像拉取失败、磁盘/权限不足 | 看服务与 Runner 日志 |
| `RESOLVING` | 仅补充入口：前置文案不存在、元素歧义、解析模型失败 | 看模型日志 `RESOLVE`，用「解析预览」核对步骤 |
| `SNAPSHOTTING` | 入口 URL / 补充目标页不可达、登录态失效、页面加载慢、前置未进入目标页 | 浏览器手动访问该 URL，核对认证内容与前置步骤 |
| `PLANNING` | 规划/补全模型超时/失败、Token 不足、页面快照为空 | 看模型日志 `PLAN` / `COVERAGE`、测试模型连通性 |
| `WAITING_APPROVAL` | 存在写/认证/危险用例或补充入口写前置，尚未审批 | 查看待审批用例，批准或只读执行 |
| `EXECUTING` | 页面交互卡住、目标站无响应、单用例步骤过多 | 看用例录屏与步骤结果 |
| `JUDGING` | 判定模型超时/失败、截图缺失 | 看模型日志 `JUDGE` 与用例证据 |
| 任务直接 `FAILED` | 依赖安装失败、快照超时、执行退出码非 0 | 看结果消息与服务日志 |

## 5. 现象 → 根因 → 验证

| 现象 | 可能根因 | 验证 |
|------|----------|------|
| 点执行提示未配置模型 | 规划/判定模型缺失 | 巡页配置中确认规划、判定已选择；解析/补全可留空 |
| 提示已有任务在执行 | 同巡页活动任务互斥 | 历史中找 `QUEUED`/`RUNNING`/`WAITING_APPROVAL` 任务 |
| 提示队列已满 | 平台默认 10 个并行、100 个排队 | 看其他巡页是否有运行中任务 |
| 判定全是规则结果 | 无判定模型、调用失败、Token 不足、输出非法 | 模型日志 `JUDGE` 状态与错误 |
| 规划用例很少/为空 | 模型失败、Token 不足、快照无交互元素 | 模型日志 `PLAN`，检查对应 Run 的状态快照 |
| 覆盖率异常低 | 元素在折叠区/iframe、滚动扫描关闭、页面文本上限过小导致模型看不到元素 | 开启滚动扫描，必要时调大页面文本上限 |
| 用例大面积 `FAILED` | 目标站异常、登录态失效、选择器不匹配 | 看录屏首屏与控制台错误 |
| 补充入口 Run 为 `UNREACHABLE` | 前置文案匹配失败、元素在折叠区/iframe、前置后未到达目标状态 | 模型日志 `RESOLVE`，用「解析预览」核对；改用 URL 型 |
| 补充入口一直待审批 | 前置含写/危险动作且未自动批准 | 批准主任务，或开启对应自动批准 |
| 补充入口覆盖偏低 | 关注点为空/太笼统、进入的页面不对 | 补充「关注点」，确认前置落点 |
| 任务完成但 `degraded=true` | 模型环节降级 | 模型日志按阶段定位 |
| 录屏缺失 | 巡页关闭用例录屏，或用例未开始执行 | 检查巡页配置与用例执行状态 |
| 历史任务消失 | 90 天保留到期清理 | 确认任务创建时间与保留策略 |
| 看不到模型日志 | 当前账号不是超级管理员 | 权限限制，属正常 |

## 6. 关键限制

| 项 | 默认值 |
|----|--------|
| 时长预算 | 20 分钟（1~60） |
| 平台并发 | 10（排队 100） |
| 模型调用超时 | 流式读取：空闲 120 秒、单次总时长 1800 秒；仅网络类失败最多 2 次尝试 |
| 调度扫描 | 60 秒 |
| 任务保留 | 90 天，每天 02:30 清理 |
| 清理批量 | 50 个任务/次 |
| 模型日志可见性 | 仅超级管理员 |

## 7. 快速恢复

1. 未配置模型：在「模型配置」创建规划与判定模型（判定勾选视觉），再回到巡页选择；解析/补全按需添加。
2. 已有任务/并发满：等待活动任务结束，或取消不再需要的任务。
3. 待审批：确认写/危险用例后「批准并执行」，或「全部拒绝（仅只读）」。
4. 模型失败：先修 Base URL/模型 ID/Key，测试连通性，再重跑巡页。
5. 时长不足：调大时长预算、缩小巡检范围或页面文本上限。
6. 入口页不可达：核对 URL、认证内容与网络访问；先在浏览器验证可打开。
7. 补充入口不可达：核对前置文案与页面实际文案，先用「解析预览」验证；能直达的改用 URL 型。
8. 定时不触发：开启定时并重新选择执行频率与时间，确认没有活动任务占位。
9. 卡死任务：先取消并等待当前步骤结束；不要直接改数据库状态。

## 8. 不要做的事

- 不要把巡页任务当成 Playwright 回归任务，去查仓库、分支或 Trace。
- 不要在未看模型日志时断言是「模型不行」；`SKIPPED` 与 `FAILED` 的根因不同。
- 不要为了让任务继续而关闭危险操作自动审批；写/删除授权需业务确认。
- 不要手工修改任务状态或 `nextRunAt` 来「修复」调度。
- 不要在普通账号下反复找「模型日志」入口；这是权限设计，不是缺陷。
- 不要泄露 API Key、认证 Cookie/Token 或完整内网地址。
