# 平台配置与权限异常排查 SOP

本 SOP 覆盖「配置能保存但语义不对」「保存时报错」「请求返回 403」「状态机不流转」四类问题。共同特征是：**代码与基础设施都正常，卡在准入规则或配置校验上**。

> 排查前提：先确认用户是不是该空间成员。跨空间、越权、共享账号造成的「看不到 / 改不了」，90% 不是 Bug。

---

## Step 1：先把问题分到 5 个域

| 域 | 典型现象 | 关键线索 |
|----|----------|----------|
| 空间与角色 | 看不到菜单、按钮置灰、403、无法加入空间 | 当前空间、成员角色、是否超管 |
| 审批流 | 申请提交失败、审批列表为空、通过后角色没变 | 申请状态、目标角色是否已拥有 |
| 仓库与凭据 | 私有仓库保存失败、拉取代码 401、凭据解密失败 | 认证方式、凭据密钥是否配置 |
| 场景配置 | 场景保存失败、保存成功但从不触发 | 仓库是否启用、cron 是否合法、名称是否重复 |
| 评测配置 | Prompt 无法编辑、Target 保存失败、Run 无法启动 | 版本状态、必填字段、SSRF、并发护栏 |

---

## Step 2：空间与角色

### 角色模型

| 角色 | 定位 | 能做什么 | 不能做什么 |
|------|------|----------|------------|
| 超级管理员 | 平台级 | 用户管理、注册开关、内置 Agent 目标、所有空间只读 | — |
| `ADMIN` | 空间管理员 | 空间设置、成员与角色、审批、全部业务操作 | 平台级管理 |
| `OPERATOR` | 空间操作者 | 仓库/场景/任务/评测的创建与修改 | 空间设置、成员管理 |
| `VIEWER` | 空间观察者 | 只读查看任务、日志、报告、评测结果 | 任何写操作 |

**常见误判**：用户说「我是管理员」，实际只是空间 `ADMIN`，不是平台超级管理员；两者权限边界不同。

### 403 家族对照

| 返回/提示 | 含义 | 处理方向 |
|-----------|------|----------|
| `space access denied` | 不是该空间的 `ADMIN` / `OPERATOR` | 查成员角色，`VIEWER` 需提权 |
| `space admin required` | 需要空间管理员 | 换 `ADMIN` 账号或走审批 |
| `super admin required` | 需要平台超级管理员 | 内置 Agent 目标、用户管理等仅超管可操作 |
| 列表为空但不报错 | 数据隔离生效，当前空间无该数据 | 确认空间切换是否正确，不是丢数据 |

### 排查顺序

1. 确认请求携带的空间与用户实际所属空间一致（切换空间后未刷新是最常见原因）。
2. 确认成员角色与操作类型匹配（写操作至少 `OPERATOR`）。
3. 确认成员状态正常，不是待审批或已移除。
4. 若涉及内置 Agent 目标（`BUILTIN_AGENT`），确认是否为超级管理员。

### 审批流异常

| 现象 | 根因 | 处理 |
|------|------|------|
| 提交申请提示 `already has requested role` | 已经是该角色 | 无需申请，刷新页面 |
| 提交申请提示 `request already pending` | 同空间已有待审批申请 | 等待审批或先撤回 |
| 审批通过后角色没变 | 审批人不是空间管理员 / 审批未真正提交 | 确认审批人角色与审批记录状态 |
| 审批列表加载失败 | 查询异常或权限不足 | 刷新重试；仍失败按 5xx 排查 |

审批状态只有 `PENDING` → `APPROVED` / `REJECTED`。通过后：申请人还不是成员则新建成员关系，已是成员则直接更新为申请的角色。

## Step 3：仓库与凭据

### 凭据密钥

私有仓库凭据使用对称加密后入库，密钥来自 `PLATFORM_CREDENTIAL_KEY`，要求 **32 字节的 base64**。

| 现象 | 根因 | 处理 |
|------|------|------|
| 保存私有仓库提示「未配置 PLATFORM_CREDENTIAL_KEY」 | 未设置密钥 | 配置密钥后重启服务；公有仓库不受影响 |
| 启动即失败「必须是 32 字节的 base64」 | 密钥长度或编码错误 | 重新生成 32 字节 base64 密钥 |
| 拉取代码提示「解密仓库凭据失败」 | 密钥被轮换或更换 | 用新密钥重新保存一次凭据 |
| 提示「仓库凭据格式不兼容，请重新保存凭据」 | 密文结构来自旧版本 | 重新录入凭据 |

**密钥轮换是有损操作**：旧密文无法用新密钥解开，必须逐仓库重新保存。排查时不要建议「随便换个密钥试试」。

### 认证方式与地址必须匹配

| 认证方式 | 只允许的地址形态 | 不匹配时的提示 |
|----------|------------------|----------------|
| `PUBLIC` | 任意合法 Git 地址 | — |
| `HTTPS_TOKEN` | `https://` | HTTPS Token 认证只能用于 https:// 仓库地址 |
| `SSH_KEY` | `ssh://` 或 `git@host:path` | SSH Key 认证只能用于 ssh:// 或 git@host:path 仓库地址 |

其他常见保存失败：

- 私有仓库但未填 Token / 私钥 → 「私有仓库需要配置 Token 或 SSH 私钥」。
- 只改了认证方式、没重新填凭据，且原凭据失效 → 同样落到上面这条。
- 凭据不会通过接口返回明文，页面显示「已配置」但看不到内容属于正常设计。

### Git 地址安全策略

平台会在服务端主动执行 `git clone`，因此地址要过安全校验。以下都会被拒绝：

| 拒绝原因 | 示例 |
|----------|------|
| 只支持 https / ssh | `file:///...`、`git://...`、`ext::...` |
| 不能以 `-` 开头 | `--upload-pack=...` 之类选项注入 |
| 不能带用户名或 token | `https://user:token@host/repo.git` |
| 不能指向本机或内网 | `localhost`、`127.0.0.1`、`10.x`、`172.16-31.x`、`192.168.x`、`169.254.x`、`::1`、`fc/fd/fe80` 段 |
| 缺少主机名 | `https:///repo.git` |

**正确做法**：地址只写 `https://host/org/repo.git`，认证信息放凭据字段，不要塞进 URL。

分支名单独校验：仅允许字母数字与 `._/-`，且不能以 `-` 开头、不能含 `..`、不能以 `/` 或 `.lock` 结尾。带空格、`~`、`^`、`:` 的分支名会被拒绝。

### 仓库启用状态

- 场景只能挂在**已启用**的仓库上；仓库停用后，新建/编辑场景会提示「所属仓库已停用，请先启用仓库」。
- 仓库被删除会级联影响其下场景，报错表现为「所属仓库不存在，请重新选择」。

## Step 4：场景保存校验

| 校验项 | 规则 | 提示/表现 |
|--------|------|-----------|
| 空间 | 必须有合法空间 | `Space not found` |
| 仓库 | 必须存在且属于同空间、已启用 | 所属仓库不存在 / 已停用 |
| 名称 | 同空间内唯一 | 名称重复保存失败 |
| 选择器 | `file` / `grep` 等类型；选择器值与匹配值会自动同步 | 保存后两个字段被补齐属正常 |
| cron | 仅在开启调度时解析 | 非法 cron 不报错，但下次运行时间为空 |

**重点陷阱：非法 cron 不报错。**
调度开启但 cron 写错时，场景能保存成功，只是永远不会触发。表现为「定时任务一直不跑」。排查时：

1. 看场景详情是否开启了调度；
2. 看是否有下次运行时间；
3. 没有下次运行时间 → 优先判定 cron 非法或为空，而不是调度器故障。

Spring cron 是 **6 段**（秒 分 时 日 月 周），写 5 段标准 Unix cron 会解析失败。

## Step 5：评测配置与状态机

### Prompt 版本

| 状态 | 含义 | 约束 |
|------|------|------|
| `DRAFT` | 草稿 | 唯一可编辑状态 |
| `ACTIVE` | 生效中 | 同 `promptKey` + 空间唯一 |
| `DEPRECATED` | 已废弃 | 被新版本替代，不自动拉取 |

| 现象 | 根因 | 处理 |
|------|------|------|
| 编辑报 `PROMPT_VERSION_CONFLICT` 「只有 DRAFT 版本可以编辑」 | 在编辑非草稿版本 | 先复制为新草稿再改 |
| 激活时报版本冲突 | 并发激活，或同 key 已有 ACTIVE | 刷新后重试，确认唯一 ACTIVE |
| 外部拉取返回 304 | ETag 未变化，协商缓存命中 | 正常现象，不是故障 |
| 外部拉取拿不到内容 | 没有 ACTIVE 版本 | 先激活一个版本 |

### Target 配置

| 类型 | 必填/关键字段 | 常见失败 |
|------|---------------|----------|
| `LLM_API` | `baseUrl`、`model`、`apiKey` | 缺字段 → `adapterConfig 缺少必填字段` |
| `HTTP_AGENT` | `endpoint` 可选 | 留空表示只接收在线 Trace，不能跑离线评测 |
| `BUILTIN_AGENT` | `agentKey` 默认 `assistant` | 未注册的 key → 「未知的内置 Agent」；非超管 → 403 |

其他规则：

- 名称同空间唯一，冲突返回 409，不是 500。
- `spaceId` 创建后不可修改。
- 类型不可识别会直接拒绝；存储时类型统一为大写枚举。
- 状态缺省 `ACTIVE`，统一大写。
- `HTTP_AGENT` 的 endpoint 在保存阶段就做 SSRF 前置校验，非法地址在保存时就会失败，不会拖到运行时。
- 内置 Agent 目标的读取、修改、删除、健康检查都要求超级管理员。

### 评测运行无法启动

| 错误码 / 提示 | 含义 | 处理 |
|---------------|------|------|
| `BAD_REQUEST`「该外部 Agent 未配置离线评测 Endpoint」 | 外部 Agent 只接了在线 Trace | 补 Endpoint，或改用在线评测 |
| `SPACE_GUARDIAN_HIT` | 同空间运行中的评测达到上限（默认 3） | 等待已有运行结束 |
| `TARGET_GUARDIAN_HIT` | 同 Target 并发运行达到上限（默认 2） | 换 Target 或稍后重试 |
| `RUN_DEDUPLICATED` | 相同配置 60 秒内重复提交 | 等待 60 秒；先查是否已有同配置运行 |
| `RUN_VERSION_CONFLICT` | 状态机乐观锁冲突 | 刷新查看真实状态，不要连续点击 |
| `TARGET_NOT_FOUND` | Target 被删除或不属于当前空间 | 确认空间与目标 ID |
| `SSRF_VIOLATION` | endpoint 指向内网/本机/非法协议 | 换合法公网地址 |

护栏命中属于**保护机制生效**，不是缺陷。回答时先说明限制值，再给替代方案，不要建议调大并发上限。

## Step 6：配置类问题的通用排查流程

```
确认空间与角色 → 确认数据归属当前空间 → 确认必填字段与格式 → 确认状态机允许该操作 → 确认安全/并发护栏 → 再看服务端错误日志
```

判断标准：

| 证据 | 置信度 |
|------|--------|
| 页面明确给出错误码或提示原文 | HIGH |
| 多个字段/状态交叉印证（如非 DRAFT + 编辑失败） | MEDIUM |
| 只看到「保存失败」无任何提示 | LOW，需要补日志或让用户复述操作 |

---

## 快速恢复建议

1. 先让用户刷新并确认当前空间，排除空间错位。
2. 权限不足走审批或换 `ADMIN` 账号，不要临时改库提权。
3. 私有仓库先确认 `PLATFORM_CREDENTIAL_KEY` 已配置且未被轮换。
4. 场景定时不跑，优先核对 6 段 cron 与「下次运行时间」。
5. 评测启动被护栏拦截，先看是否有同配置运行未结束。
6. 配置类问题一律保留原始报错文本与错误码，便于定位。

## 禁止事项

- 不修改数据库中的角色、状态、凭据字段。
- 不建议绕过安全策略（去掉 SSRF 校验、允许内网地址、URL 内嵌 token）。
- 不在回答中输出密钥、Token、私钥、完整仓库地址或密文。
- 不把护栏触发的正常拦截描述成系统故障。
