# 平台总览

## 1. 平台定位

**易测**是面向研发与测试团队的一站式质量平台，解决两件事：

1. **UI 自动化回归**：把 Playwright 测试项目接进来，按场景定时或手动执行，统一收集日志、用例结果、截图、视频与 Trace。
2. **大模型效果评测**：把 Prompt、被评目标、评测集管起来，支持离线批跑、评分、在线 Trace 监控与低分巡检。

平台内置智能助手 **知知**，负责业务知识问答与平台错误排查。

## 2. 能力地图

| 领域 | 模块 | 解决什么问题 |
|------|------|--------------|
| 账号与空间 | 登录注册、昵称、空间广场、成员、加入审批 | 谁能在哪个团队里做什么 |
| UI 自动化 | 仓库管理、场景管理、任务执行、日志与产物 | E2E 用例自动化执行与结果定位 |
| AI 助手 | 知知对话、工具调用、技能、额度 | 业务答疑与故障根因分析 |
| 模型评测 | Prompt 托管、被评目标、评测集、离线评测、在线监控 | Prompt/模型/Agent 的效果对比与线上质量巡检 |
| 平台运维 | 用户管理、注册开关、审计 | 全平台账号与注册策略治理 |

## 3. 典型角色

| 角色 | 主要诉求 |
|------|----------|
| 测试工程师 | 配场景、跑任务、看失败用例与产物 |
| 空间管理员 | 审批加入、维护成员角色、管理空间资源 |
| 评测负责人 | 维护 Prompt、Target、Dataset，跑离线评测与在线策略 |
| 值班/排障人员 | 按 traceId、任务、策略快速定位异常 |
| 超级管理员 | 跨空间排障、用户管理、注册开关 |

## 4. 技术架构（业务视角）

```
前端：Vue 3 + TypeScript + Element Plus（页面与交互）
后端：Spring Boot 3 + MyBatis（业务与编排）
AI  ：基于 ReAct 循环的智能体（知知），按需调用平台只读工具
基础设施：MySQL（业务数据）、Redis（缓存/租约）、MinIO（日志与产物）、
          Docker（Playwright Runner）、Flyway（Schema 版本）、Langfuse（Trace 与评分）
```

关键设计：

- **空间隔离**：所有业务数据按 spaceId 隔离，助手工具自动限定当前空间。
- **短生命周期 Runner**：每个任务在独立 Docker 容器中执行，结束后清理 workspace。
- **按需加载知识**：技能只加载索引，模型判断需要时再加载正文，控制上下文成本。
- **降级优先**：Trace 写入、在线监控等非核心链路失败时降级，不阻断主流程。

## 5. 核心对象关系

```
空间 Space
  ├── 仓库 Repository 1:N
  ├── 场景 Scene 1:N
  │     └── 任务 Task 1:N
  │           ├── 阶段日志 TaskStageLog
  │           ├── 用例结果 CaseResult
  │           └── 产物 Artifact（截图/视频/Trace/报告）
  ├── 成员 SpaceMember
  ├── 加入申请 SpaceAccessRequest
  ├── 被评目标 Target 1:N
  ├── 评测集 Dataset 1:N（内含用例 Sample）
  ├── Prompt 1:N 版本
  ├── 离线评测 Offline Run 1:N
  └── 在线策略 Online Policy 1:N
```

关联关系：

- 一个仓库可以被多个场景复用；一个场景对应一个仓库与分支。
- 任务由场景产生，保留场景配置的「解析后快照」，场景后续修改不影响历史任务。
- 离线评测绑定「被评目标 + 评测集 + 用例范围 + 并发数」，一次运行产生多条用例结果。
- 在线监控以 Langfuse Trace 为准，平台不重复存储原始链路。

## 6. 状态机

### 6.1 任务

| 状态 | 含义 |
|------|------|
| `QUEUED` | 已创建，等待执行线程池调度 |
| `RUNNING` | 正在执行某个阶段 |
| `SUCCESS` | 安装与测试阶段均成功 |
| `FAILED` | 安装或测试阶段失败 |
| `TIMEOUT` | 安装或测试阶段超时 |
| `CANCELED` | 用户取消或恢复逻辑判定取消 |

阶段：`PREPARING`（准备 workspace/拉代码）→ `INSTALLING`（安装依赖）→ `TESTING`（执行测试）→ `ARCHIVING`（归档产物/解析用例）→ `FINISHED`。

结果码：`SUCCESS`、`INSTALL_FAILED`、`PREPARE_FAILED`、`TEST_FAILED`、`TIMEOUT`、`CANCELED`。

用例状态：`PASSED`、`FAILED`、`TIMEOUT`、`SKIPPED`。

> 任务 `SUCCESS` 表示命令退出码为 0，不等同于所有用例都 PASSED；用例级失败要看用例结果。

### 6.2 Prompt 版本

`DRAFT` → `ACTIVE` → `DEPRECATED`；同一 key 同一时间只允许一个 `ACTIVE`，激活新版本会自动废弃旧版本。

### 6.3 离线评测运行

`PENDING` → `RUNNING` → `COMPLETED` / `FAILED` / `CANCELLED`。

### 6.4 在线策略

`ACTIVE`（周期扫描）/ `PAUSED`（手动暂停或 Langfuse 不可用时自动暂停）。

### 6.5 目标与接入

- 被评目标状态：默认 `ACTIVE`，停用后不能新建评测运行，历史结果保留。
- 外部 Agent 接入状态：`CONNECTED` / `DISABLED`。

## 7. 数据隔离与权限

| 规则 | 说明 |
|------|------|
| 空间隔离 | 仓库、场景、任务、评测资源的查询都强制带 spaceId |
| 角色 | `ADMIN` 全部能力；`OPERATOR` 可创建/编辑/触发；`VIEWER` 只读 |
| 超级管理员 | 跨空间视为 `ADMIN`，可进入用户管理 |
| 前端守卫 | 菜单与路由守卫只影响体验，后端才是安全边界 |
| 助手工具 | spaceId 由服务端绑定，工具不接受外部传入 |

## 8. 关键全局限制

| 项 | 默认值 / 规则 |
|----|---------------|
| 任务执行线程池 | 核心 2、最大 4、队列 50 |
| 队列满 | 新任务直接失败，不无限排队 |
| 安装超时 | 600 秒 |
| 测试超时 | 1800 秒 |
| 单个产物 | 100MB；单任务产物总量 1GB |
| 测试日志 | 单文件上限 200MB |
| 任务保留 | 默认不自动清理，生产建议 90 天 |
| Runner | 2GB 内存 / 2 CPU / bridge 网络 |
| AI 每日额度 | 单用户 50 次；全局并发 4 |
| AI 单次对话 | 最多 20 次模型调用；单次模型超时 60 秒、重试 2 次 |
| 调度扫描 | 每 60 秒扫描到期场景 |
| 调度租约 | 同一场景同一触发时刻 2 分钟内不会被重复触发 |
