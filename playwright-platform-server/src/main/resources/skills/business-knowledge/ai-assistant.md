# AI 智能助手：知知

## 1. 定位

**知知**是易测平台的智能助手，只做两件事：

1. **业务知识问答**：解释平台模块、操作步骤、规则限制、角色权限、状态与术语。
2. **平台错误排查**：基于当前空间的真实数据，定位 UI 自动化、平台基建与大模型评测类故障的根因。

知知不是通用聊天机器人，不执行写操作，也不跨空间查询。

## 2. 入口与交互

| 功能 | 说明 |
|------|------|
| 打开助手 | 页面右下角悬浮按钮，全局可用 |
| 快捷问题 | 对话框顶部推荐问题，一键填入 |
| 发送消息 | 输入框回车或发送按钮；流式返回，可中途停止 |
| 停止生成 | 生成中的「停止」按钮，中断当前流 |
| 清空对话 | 重置当前会话上下文 |
| 任务上下文分析 | 任务详情页「AI 分析」，自动携带任务、场景、阶段日志 |

## 3. 能做什么

| 能力 | 说明 | 典型问法 |
|------|------|----------|
| 业务问答 | 平台功能、规则、角色、术语 | 「场景的 Cron 怎么写」「VIEWER 能触发任务吗」 |
| 信息查询 | 查任务、场景、仓库的当前数据 | 「任务 #123 为什么一直排队」 |
| 故障分析 | 结合日志与配置定位根因 | 「帮我分析任务 #123 的失败原因」 |
| 评测排障 | Target、Dataset、离线运行、在线策略、Langfuse | 「离线评测一直 RUNNING 是什么原因」 |
| 链路回溯 | 按 traceId 查知知自身调用链 | 「这次回答为什么格式不对」 |

## 4. 可用工具

| 工具方法 | 用途 |
|----------|------|
| `listTasks(sceneId)` | 列出当前空间任务，可按场景过滤 |
| `getTask(taskId)` | 任务状态、阶段、统计、结果消息、阶段日志预览 |
| `analyzeLogs(taskId)` | 提取阶段日志错误行与失败用例摘要 |
| `listScenes(repoId)` | 列出场景，可按仓库过滤 |
| `getSceneDetail(sceneId)` | 场景配置详情（分支、选择器、浏览器、Cron、环境变量数量） |
| `searchRepository(keyword)` | 按名称搜索仓库 |
| `getRepository(repositoryId)` | 仓库配置详情（地址脱敏、分支、测试根目录、执行命令） |
| `loadSkillContent(skillName)` | 加载技能正文 |
| `loadSkillDocument(skillName, docName)` | 加载技能子文档（具体 SOP） |

工具是**只读**的，且自动限定当前空间；用户无法让知知修改数据。

## 5. 知识与技能

| 技能 | 作用 | 加载方式 |
|------|------|----------|
| `business-knowledge` | 平台业务知识库 | 启动只加载索引，按需加载正文与子文档 |
| `error-analysis` | 六类故障排查 SOP | 同上 |

这种「索引 + 按需加载」的方式能显著减少上下文占用，同时保证专业问题能查到细节。

## 6. 关键规则与限制

| 规则 | 默认值 / 说明 |
|------|--------------|
| 单用户每日调用 | 50 次，超出提示「今日 AI 调用次数已达上限」 |
| 全局并发 | 4 路，超出提示「当前繁忙」 |
| 单次对话模型调用 | 最多 20 次，超过熔断，防止死循环 |
| 单次模型超时 | 60 秒，最多重试 2 次 |
| 上下文压缩 | Token 超过上限 80% 或消息数超过 50 时触发；保留最近 3 条并摘要历史 |
| 单条消息截断 | 4000 字符 |
| 输入清洗 | 超长或含注入特征会被拒绝 |
| 输出格式 | 结构化 sections：`heading` / `paragraph` / `list` / `code` / `quote` / `table` |
| 会话存储 | 本地会话缓存，默认 30 分钟过期；多实例部署需迁移到共享存储 |
| 全链路 Trace | 写入 Langfuse，可在「在线监控」按 traceId 查看 |

## 7. 回答结构

知知返回的不是一段纯文本，而是结构化块：

- 顶层字段：`sections`、`usedTools`、`confidence`、`responseType`、`faultDetail`。
- `responseType`：`FAULT_ANALYSIS`（故障分析）/ `BUSINESS_QA`（业务问答）/ `INFORMATION_QUERY`（信息查询）/ `UNKNOWN`。
- `confidence`：`HIGH` / `MEDIUM` / `LOW`，表示证据充分程度。
- `faultDetail`：仅故障分析时出现，包含故障类型、根因、临时方案、长期优化、测试风险、复现步骤。

## 8. 典型流程

### 8.1 分析一个失败任务

1. 打开失败任务详情，点「AI 分析」。
2. 知知读取任务状态、当前阶段、阶段日志与失败用例。
3. 必要时查相邻任务、场景配置、仓库配置，或压缩日志。
4. 输出结构化结论：失败阶段 → 直接原因 → 证据 → 修复建议。

### 8.2 咨询平台功能

1. 直接提问，例如「怎么配置每天凌晨两点的回归」。
2. 知知判断属于业务问答，加载 `business-knowledge` 对应模块。
3. 返回结论 + 操作步骤 + 规则限制。

## 9. 常见问题

| 现象 | 排查 |
|------|------|
| 提示「今日 AI 调用次数已达上限」 | 等待次日重置或联系管理员调整额度 |
| 提示「当前繁忙」 | 全局并发已满，稍后重试 |
| 回答与当前空间无关 | 确认已切换到目标空间再打开助手 |
| 一直无响应后超时 | 模型接口不可达或 API Key 无效，检查服务端日志 |
| 看不到 AI 给的数据 | 知知只读取当前用户有权限的数据 |
| 多实例下会话丢失 | 本地会话不共享，需要共享存储改造 |
| 回答格式不是结构化块 | 检查系统提示词与输出兜底日志，联系管理员 |
