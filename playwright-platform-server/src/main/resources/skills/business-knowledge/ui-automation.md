# UI 自动化：仓库、场景与任务

## 1. 业务定位

UI 自动化主线由三段组成：

```
仓库 Repository（测试代码从哪来、怎么跑）
    ↓
场景 Scene（跑哪个分支、哪些用例、什么浏览器、什么时候跑）
    ↓
任务 Task（一次真实执行：阶段日志 + 用例结果 + 产物）
```

## 2. 仓库管理

### 2.1 作用

仓库是执行源：平台按仓库配置把 Playwright 测试项目拉进 Runner 容器，安装依赖、执行测试，再回传结果与产物。一个空间可以有多个仓库，一个仓库可以被多个场景复用。

### 2.2 关键字段

| 字段 | 用途 | 注意 |
|------|------|------|
| 仓库名称 | 空间内唯一标识 | 重名返回冲突 |
| Git 地址 | 测试项目地址 | `PUBLIC`/`HTTPS_TOKEN` 用 `https://`；`SSH_KEY` 用 `ssh://` 或主机别名 |
| 默认分支 | 场景未指定分支时使用 | 建议填 `main` 等主干分支 |
| 工作目录 | 仓库内执行相对目录 | 必须在仓库根目录内 |
| 安装命令 | 如 `npm ci` | 默认超时 600 秒 |
| 执行命令模板 | 如 `npx playwright test` | 支持场景级覆盖 |
| 测试根目录 | 用例目录 | 用于定位测试 |
| 结果索引路径 | Playwright JSON 报告路径 | 默认 `test-results/.playwright-results.json` |
| 产物目录 | 截图/视频/Trace 目录 | 默认 `.playwright-artifacts` |
| 认证方式 | `PUBLIC` / `HTTPS_TOKEN` / `SSH_KEY` | 与凭据配套 |
| 凭据 | 用户名 + Token / 私钥 | 仅提交时加密落库，读取不返回明文 |

### 2.3 规则与限制

| 规则 | 说明 |
|------|------|
| 名称唯一 | 同一空间内仓库名称唯一 |
| URL 校验 | 不接受不安全协议 |
| 凭据加密 | 使用 AES-256-GCM 加密；编辑时留空表示保留旧凭据 |
| 私有仓库 | 未配置匹配凭据时，任务在拉取阶段失败 |
| 停用仓库 | 停用后不能创建新场景引用，历史任务仍可查看 |
| 删除仓库 | 被场景引用时需先解除引用 |

## 3. 场景管理

### 3.1 作用

场景是「一次测试执行」的配置模板：选哪个仓库、哪个分支、跑哪些用例、用什么浏览器、注入哪些环境变量、是否定时执行。任务由场景触发产生，同一场景可以反复执行。

### 3.2 表单字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 场景名称 | 是 | 空间内唯一 |
| 场景描述 | 否 | 业务说明，便于团队识别 |
| 所属仓库 | 是 | 仅可选择启用状态的仓库 |
| 分支 | 是 | 默认取仓库默认分支 |
| 测试选择器类型 | 是 | 按文件/标题/标签等，决定匹配值含义 |
| 匹配值 | 视选择器 | 文件路径、用例标题或标签 |
| 浏览器 | 是 | `chromium` / `firefox` / `webkit` |
| 环境变量 JSON | 否 | 注入 Runner，必须是合法 JSON |
| 启用定时 | 否 | 打开后填写 Cron |
| Cron 表达式 | 定时开启时必填 | 秒级 6 段或标准 5 段 |
| 运行命令 | 否 | 覆盖仓库的执行命令模板 |

### 3.3 规则与限制

| 规则 | 说明 |
|------|------|
| 名称唯一 | 同一空间内场景名称唯一 |
| 仓库可用性 | 仓库不存在或已停用时拒绝保存 |
| Cron 合法性 | 保存时解析 Cron，非法表达式直接报错 |
| 调度扫描 | 调度线程每 60 秒扫描到期场景，按 `nextRunAt` 触发 |
| 触发幂等 | 同一场景同一触发时刻只生成一个任务；调度租约有效期 2 分钟 |
| 调度事件 | 定时触发产生调度事件；失败可按可重试性分类并重试 |
| 删除场景 | 不影响已产生的任务与产物，但后续无法再触发 |

### 3.4 典型流程：配置每日凌晨回归

1. 新增场景，选择回归测试仓库与 `main` 分支。
2. 选择器选「按标签」，匹配值填 `@regression`。
3. 浏览器选 `chromium`，按需补充环境变量 JSON。
4. 打开「启用定时」，填写 `0 0 2 * * ?`（每天 02:00）。
5. 保存后确认「执行模式」为定时。
6. 次日检查任务列表是否按预期产生任务；异常时看调度事件。

## 4. 任务执行

### 4.1 任务是什么

任务是一次真实的 Playwright 执行记录：由场景手动或定时触发，在 Docker Runner 短生命周期容器中运行，结束后归档阶段日志、截图、视频、Trace 与结构化用例结果。

### 4.2 任务状态

| 状态 | 含义 |
|------|------|
| `QUEUED` | 已创建，等待线程池调度 |
| `RUNNING` | 正在执行 |
| `SUCCESS` | 安装与测试命令均成功 |
| `FAILED` | 安装或测试失败 |
| `TIMEOUT` | 安装或测试超时 |
| `CANCELED` | 已取消 |

> `SUCCESS` 只代表命令退出码为 0，不代表所有用例都通过；用例是否通过看 `PASSED/FAILED/TIMEOUT/SKIPPED`。

### 4.3 执行阶段

| 阶段 | 做什么 | 失败常见方向 |
|------|--------|--------------|
| `PREPARING` | 准备 workspace、拉代码、解析路径 | Git 地址、分支、凭据、workspace 权限 |
| `INSTALLING` | 安装依赖 | 依赖源、安装命令、网络、超时 |
| `TESTING` | 执行 Playwright | 用例逻辑、环境、数据、选择器、断言 |
| `ARCHIVING` | 归档产物、解析用例结果 | 结果索引路径、产物目录、存储 |

### 4.4 结果码

`SUCCESS`、`INSTALL_FAILED`、`PREPARE_FAILED`、`TEST_FAILED`、`TIMEOUT`、`CANCELED`。

### 4.5 任务详情结构

1. **概览**：状态、触发方式、开始/结束时间、耗时、场景与分支。
2. **阶段日志**：按阶段归档，支持预览与下载。
3. **用例结果**：来自 Playwright JSON reporter，含状态、耗时、错误摘要。
4. **产物**：截图、视频、Trace、报告；下载链接为 MinIO 预签名 URL，有效期约 1 小时。

### 4.6 操作

| 功能 | 说明 |
|------|------|
| 立即执行 | 在场景任务页手动创建一个任务 |
| 查看详情 | 阶段、用例结果、日志、产物 |
| 取消任务 | 仅运行中的任务可取消；协作式取消，非强制杀进程 |
| 重新执行 | 以相同场景配置创建**新任务**，不复用旧记录 |
| AI 分析 | 把任务上下文交给知知生成失败分析 |
| 查看 Trace | 打开 Playwright Trace 查看器 |

### 4.7 规则与限制

| 规则 | 默认值 / 说明 |
|------|--------------|
| 执行线程池 | 核心 2、最大 4、队列 50 |
| 队列满 | 新任务直接失败并提示队列已满 |
| 安装超时 | 600 秒 |
| 测试超时 | 1800 秒 |
| 取消机制 | 通过取消标记轮询生效，等待当前阶段结束或超时 |
| 单产物大小 | 100MB |
| 产物总量 | 1GB |
| 测试日志 | 200MB |
| 保留策略 | 默认 `0` 不自动清理；生产建议 90 天 |
| Runner 资源 | 2GB 内存 / 2 CPU / bridge 网络 |
| 服务重启 | 启动恢复逻辑会把遗留 `RUNNING` 标记失败，`QUEUED` 未取消的重新派发 |

> 任务状态由平台维护，不要手工改数据库状态。

## 5. 典型流程：定位一次失败回归

1. 在任务列表按结果归因筛选失败任务，打开详情。
2. 看「当前阶段」：停在 `INSTALLING` 多为依赖/网络；停在 `TESTING` 进入用例结果。
3. 在用例结果中筛失败用例，点「查看 Trace」看失败步骤与截图。
4. 下载截图/视频附到缺陷单。
5. 需要文字分析时点「AI 分析」，让知知结合阶段日志与用例结果给原因假设。
6. 修复后点「重新执行」。

## 6. 常见问题

| 现象 | 排查 |
|------|------|
| 一直 `QUEUED` | 线程池已满或 Runner 不可用；看队列容量与服务日志 |
| `PREPARING` 失败 | 仓库地址、分支、凭据、workspace 权限 |
| `INSTALLING` 超时 | 依赖安装慢；调整安装命令或调大超时 |
| `TESTING` 无结果 | reporter 未输出 JSON，或结果索引路径配置错误 |
| 产物下载 403/过期 | 预签名 URL 约 1 小时有效，重新打开详情获取新链接 |
| 取消后仍显示 `RUNNING` | 取消是协作式的，等待当前阶段结束或超时 |
| 服务重启后任务变 `FAILED` | 启动恢复逻辑把遗留 `RUNNING` 标记失败，需重新执行 |
| 场景执行选不到用例 | 选择器类型与匹配值和仓库内测试结构不一致 |
